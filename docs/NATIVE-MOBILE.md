# Moonwater Native Mobile Shell

Moonwater remains a React 19 + TypeScript + Vite app. Capacitor 8 packages that existing production build in native Android and iOS shells:

```text
React / Vite source → `npm run build` → `dist/` → Capacitor sync → Android or iOS shell
```

The normal `npm run dev` browser workflow is unchanged. The web build uses Vite's existing root-relative assets and `dist` output; the app is a component-state SPA and does not depend on browser-only route navigation. Capacitor was suitable in the audit: the game is portrait-first, UI-heavy, uses local storage and 2D canvas, and has no PWA service worker or file-protocol dependency.

## Native identifiers and current plugins

- App name: **Moonwater**
- Android application ID: `com.moonwater.game`
- iOS bundle ID: `com.moonwater.game`
- Capacitor: `@capacitor/core`, `@capacitor/cli`, `@capacitor/android`, `@capacitor/ios` (8.x)
- Native plugins: `@capacitor/app` (resume and Android Back), `@capacitor/haptics`, and `@capacitor/status-bar`

`src/platform/` keeps platform checks and native APIs out of game systems. Haptics are no-ops in web builds. The icon and splash artwork is temporary pixel Moonwater artwork generated by `scripts/generate-native-assets.mjs`; replace it with approved production artwork later.

## Local Android setup on Windows

Install Android Studio and the Android SDK platform/build tools recommended by SDK Manager. Use a Java version supported by this project's Gradle wrapper and Android Gradle Plugin. On the current development machine, Android Studio's bundled Java 25 was found, but the Gradle build failed with unsupported class-file version 69; use a compatible JDK 21 for this project. The web assets sync successfully, but APK/device verification has not been completed.

From the repository root:

```powershell
npm install
npm run mobile:sync
npm run mobile:android
```

`mobile:sync` builds the production web app, regenerates temporary native artwork, and copies the result/plugins into both platform projects. `mobile:android` then opens Android Studio. In Android Studio, wait for Gradle sync, choose an installed emulator or a connected device, and press Run. To build an APK from the command line after Android Studio has configured the SDK:

```powershell
cd android
.\gradlew.bat assembleDebug
```

The debug APK is written under `android/app/build/outputs/apk/debug/`. For a physical Android phone, enable Developer options and USB debugging, connect by USB, accept the computer's debugging prompt, confirm it appears in `adb devices`, then run the app from Android Studio. The manifest locks the activity to portrait.

## iOS on a Mac

The iOS Capacitor project and plugin registration are generated. Windows cannot compile, sign, boot a simulator, or install it on an iPhone; no iOS device validation has been done.

On a Mac with Xcode installed, from the repository root:

```sh
npm install
npm run mobile:sync
npm run mobile:ios
```

In Xcode, select the Moonwater app target, set a development signing team, choose an iPhone simulator or connected iPhone, and run. The prepared bundle ID is `com.moonwater.game`; the Info.plist limits supported orientations to portrait. Physical installation requires normal Apple development signing. TestFlight and store publication are outside this phase.

## Backend and environment configuration

Values with a `VITE_` prefix are compiled into the client and must be considered public. Supabase URL and anon key are public client values. Never put a Supabase service-role key or another secret in a Vite variable or Capacitor config.

Web Friendly Battle keeps using same-origin `/api/...` requests when `VITE_API_BASE_URL` is unset. A packaged app needs the public HTTPS origin of the deployed Moonwater API, with no trailing slash or `/api`, for example:

```dotenv
VITE_API_BASE_URL=https://your-moonwater-host.example
```

Set this before `npm run mobile:sync`; the value is baked into the app build. Configure the API host's server-only `CAPACITOR_ALLOWED_ORIGINS` allowlist with the Capacitor origins used by the targets, typically `https://localhost,capacitor://localhost`. The API handlers answer preflight requests and allow only configured origins. Add the same origins to the Supabase project's allowed origins for native WebView auth, REST, and realtime requests. Friendly Battle still needs a reachable HTTPS backend; local game and saved progression do not depend on the browser dev server.

Remote config currently uses the repository's existing config abstraction and local defaults; no new remote-config fetch is added here. Offline play can use locally stored systems; network-backed Friendly Battle and remote Supabase activity require connectivity and report request failures through their existing UI. Google Fonts can fall back to system fonts offline.

## Lifecycle, storage, appearance, and Android Back

The platform lifecycle bridge normalizes Capacitor foreground transitions and browser visibility transitions. On resume, Home reloads Campaign progress, Energy, Idle Gold, and its elapsed-time note; Journey and Missions recompute their day/week view. Energy and idle reward calculations use persisted timestamps, so elapsed time includes time in the background and after process restarts. Other game state remains in the existing localStorage stores; Capacitor WebView storage normally survives force-close and app updates, but uninstalling/clearing app data removes it. Persistence has not yet been observed across an actual device restart on this machine.

The document viewport enables `viewport-fit=cover`; existing shared screen styles already use safe-area environment values for bottom navigation, sheets, and full-screen ritual content. The native status bar uses light foreground icons on Moonwater's dark background and does not overlay the web view. Android Back sends Escape to the top visible dialog first, returns full-screen destinations to their existing parent state, then navigates to Home from another tab; only Home exits the app. Orientation is portrait on both platforms.

Haptics are limited to Hero Level, Ascension, Star gain, Campaign victory/chapter completion, and Legendary reveal. Hardware capability and tactile feel remain unverified because there is no Android device/emulator available here.

## Sync and development workflow

1. Make normal React/TypeScript changes and use `npm run dev` for browser iteration.
2. Run `npm run check` for lint, unit tests, TypeScript, and production build.
3. Set the intended public mobile environment values, then run `npm run mobile:sync`.
4. Run/open the platform project from Android Studio or Xcode.

Never point a production app at the Vite dev server. Capacitor live reload is a temporary developer-only option and should not be committed as the shipped `server.url`.
